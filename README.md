# Анализ сайта «СберАвтоподписка»: предсказание конверсии визита

Учебная задача хакатона МИФИ (Skillfactory, «Проектный практикум»). По данным визита на сайт —
откуда пришёл человек (UTM-метки), с какого устройства, из какого города и в какое время — модель
предсказывает, совершит ли он **целевое действие**: оставит заявку, закажет звонок, откроет диалог и т.п.

Модель нужна, чтобы:
- оценивать эффективность каналов привлечения трафика;
- перераспределять рекламный бюджет в пользу каналов, которые приводят «горячих» посетителей;
- персонализировать сайт для посетителей с высокой вероятностью заявки.

**Метрика:** ROC-AUC на отложенной выборке, ориентир по брифу — **≈ 0.65**.

---

## 📊 Данные

Google Analytics сайта (май–декабрь 2021):
- `ga_sessions.pkl` — 1,86 млн визитов: UTM-метки, устройство, гео, дата/время, номер визита клиента;
- `ga_hits.pkl` — 15,7 млн событий внутри визитов (страницы, клики, действия).

**Таргет:** визит = 1, если в нём было хотя бы одно действие из списка
`sub_car_claim_click`, `sub_car_claim_submit_click`, `sub_open_dialog_click`, `sub_custom_question_submit_click`,
`sub_call_number_click`, `sub_callback_submit_click`, `sub_submit_success`, `sub_car_request_submit_click`.
Конверсия ≈ **2,9%** (сильный дисбаланс классов).

Сырые данные в репозиторий не входят (≈ 5 ГБ): положите `ga_sessions.pkl` и `ga_hits.pkl` в `data/raw/`.

## 🧠 Подход

1. **Подготовка данных** — `notebooks/01_preprocessing.ipynb`: качество данных (пропуски, `(not set)`, дубликаты),
   определение таргета, сборка таблицы «один визит — одна строка».
   **EDA** — `notebooks/02_eda.ipynb`: распределения, конверсия по каналам, устройствам, городам и времени,
   динамика по неделям, корреляции.
2. **Признаки** — `src/features.py`, общий для обучения и API. Только то, что известно **в момент начала визита**:
   - UTM-метки и связка «источник + тип трафика»;
   - устройство, ОС, браузер, связка «тип устройства + ОС», размеры экрана;
   - город, страна;
   - час, день недели, выходной;
   - номер визита и флаг «новый посетитель», флаг органического трафика.
3. **Модель** — `notebooks/03_model.ipynb`:
   - одна строка = один визит;
   - сплит **по времени** 70/15/15 (учимся на ранних датах, тестируемся на последних неделях декабря);
   - сравнение: бейзлайн «конверсия канала» → логистическая регрессия → **CatBoost**;
   - порог для ответа 0/1 подобран по F1 на валидации.

### Результаты (ROC-AUC на отложенном тесте)

| Модель | Случайный сплит 70/30 (как в задании) | Сплит по времени (тест — последние 3 недели декабря) |
| --- | --- | --- |
| Бейзлайн: конверсия канала «источник + тип трафика» | 0.636 | 0.537 |
| Логистическая регрессия | 0.681 | 0.628 |
| **CatBoost** | **0.705** ✅ | **0.628** |

- Ориентир брифа (≈ 0.65) достигнут: **ROC-AUC 0.705** на случайном стратифицированном сплите, +0.07 к бейзлайну.
- Проверка на будущих датах строже: 0.63. Разница — из-за дрейфа данных: в декабре другие рекламные кампании
  и ниже конверсия (2,0% против 3,3% в мае–ноябре), а модель знает только прошлое. Поэтому финальная модель
  для API обучена на всех данных, включая декабрь.
- **Лифт:** среди 10% визитов с самой высокой оценкой конверсия **8,1%** — в 2,8 раза выше средней; в эти 10% попадает
  **28% всех конверсий**, в топ-20% — 45%.
- Ответ 0/1 в API — по порогу 0.06 (подобран по F1): ответ «1» получают ~6,5% визитов, их конверсия в 3,2 раза выше средней.

**Важные признаки:** рекламное объявление и кампания (`utm_adcontent`, `utm_campaign`), источник трафика,
органика/реклама, номер визита. Время визита и гео влияют слабо.

### 💡 Выводы для бизнеса

1. **Органический и реферальный трафик конвертируется почти вдвое лучше платного** (≈ 4,4% против 2,3%; referral — 6,0%).
   Самые слабые платные каналы — `cpm` (1,1%), `stories` (1,2%), `email` (1,4%): их бюджет стоит пересмотреть
   в пользу кампаний и объявлений, которым модель даёт высокую оценку.
2. **Вернувшиеся посетители конвертируются в ~1,7 раза лучше новых** (≈ 4,2% против 2,5%) — ретаргетинг и push
   на тех, кто уже был на сайте, окупаются лучше привлечения новых.
3. **Персонализация по оценке модели:** посетителям из топ-10% по вероятности (каждый 12-й из них оставляет заявку)
   можно сразу показывать форму обратного звонка или чат — это 28% всех конверсий при 10% трафика.
4. Десктоп конвертируется лучше мобильных (≈ 3,3% против 2,8%) — стоит проверить мобильную версию
   формы заявки на удобство.

### 🔍 Работа над ошибками: утечка таргета

Первая версия модели показывала ROC-AUC 0.895 — слишком хорошо для такой задачи. Причина оказалась в утечке:
модель обучалась на отдельных событиях, а не на визитах, и среди признаков было число целевых действий в сессии
(по сути сам ответ) и данные, известные только после визита. Текущая версия считает всё на уровне визита,
использует только признаки «до визита» и дополнительно проверяется на будущих датах.

## 🚀 Запуск API

```bash
git clone https://github.com/listaloe/MIFIHackatonSberAutoSubscriptionAnalysis.git
cd MIFIHackatonSberAutoSubscriptionAnalysis
pip install -r requirements.txt
uvicorn src.api:app --host 0.0.0.0 --port 8000
```

Модель `catboost_sessions_v2.cbm` весит ~160 МБ и не помещается в git (лимит GitHub — 100 МБ):
скачайте её из [Releases](https://github.com/listaloe/MIFIHackatonSberAutoSubscriptionAnalysis/releases)
и положите в `data/models/` — либо обучите заново ноутбуком `notebooks/03_model.ipynb`.
Метаданные (признаки, порог, метрики) — в `data/models/catboost_sessions_v2_meta.json`.
Документация API: http://localhost:8000/docs

### `GET /health`
```json
{"status": "ok", "model": "catboost_sessions_v2.cbm", "roc_auc_test": 0.7048}
```

### `POST /predict`
Принимает один или несколько визитов в формате `ga_sessions`. Обязательны только `visit_date` и `visit_time`,
остальные поля можно не передавать — они будут считаться пропусками.

```json
{
  "data": [
    {
      "session_id": "5692861315757623740.1632356796.1632356796",
      "visit_date": "2021-12-20",
      "visit_time": "14:05:00",
      "visit_number": 1,
      "utm_source": "ZpYIoDJMcFzVoPFsHGJL",
      "utm_medium": "banner",
      "utm_campaign": "LEoPHuyFvzoNfnzGgfcd",
      "utm_adcontent": "vCIpmpaGBnIQhyYNkXqp",
      "utm_keyword": "puhZPIYqKXeFPaUviSjo",
      "device_category": "mobile",
      "device_os": "Android",
      "device_brand": "Huawei",
      "device_screen_resolution": "360x720",
      "device_browser": "Chrome",
      "geo_country": "Russia",
      "geo_city": "Moscow"
    }
  ]
}
```

Ответ: вероятность целевого действия и решение 0/1 по порогу модели.
```json
{
  "threshold": 0.0605,
  "predictions": [
    {"session_id": "5692861315757623740.1632356796.1632356796", "probability": 0.021, "prediction": 0}
  ]
}
```

### Тесты
```bash
pytest -q
```
Проверяются `/health`, `/predict` (в том числе с минимальным набором полей и некорректным запросом)
и время ответа: 1000 визитов обрабатываются быстрее 3 секунд (требование брифа).
